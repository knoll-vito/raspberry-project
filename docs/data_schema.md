# 真实灾情数据 · 输入 schema

供"灾后伤亡风险评估系统"的 Teacher 标注阶段使用。每条样本对应一次具体灾害事件中**某一时间点**的态势快照（不是事件全过程）。

## 总体原则

- 一行一个样本 = 一次事件的一个观测时间点
- 每个事件可以贡献**多条样本**（例如汶川地震在第 1h、6h、24h、72h 各采一次）
- 字段类型严格按下表填写；不确定就留空，转换脚本会标记为缺失
- 每条都需要至少 7 个核心特征到位才能进入训练；少于 6 个会被过滤掉
- 推荐先攒 **50~80 条高质量真实样本**，再放量；质量 > 数量

## 字段表

| # | 字段名 | 类型 | 必填 | 取值范围 | 单位/说明 |
|---|---|---|---|---|---|
| 1 | `event_name` | string | 否 | 自由文本 | 事件标识（如"2008汶川地震-北川县观测点"），便于追溯 |
| 2 | `source` | string | 否 | 自由文本 | 数据来源（论文标题/政府报告/新闻链接），方便 audit |
| 3 | `disaster_type` | enum | **是** | 见下方 | 灾种（5 选 1）|
| 4 | `magnitude` | float | **是** | 3.0 ~ 8.5 | 灾害强度，归一化到这一区间（见下方映射表）|
| 5 | `building_collapse_rate` | float | **是** | 0.0 ~ 1.0 | 受影响区域内建筑倒塌比例 |
| 6 | `estimated_trapped` | int | **是** | 0 ~ 10000 | 估计被困/受困人数 |
| 7 | `temperature_c` | float | **是** | -40 ~ 50 | 当时环境温度（℃）|
| 8 | `hours_since_disaster` | float | **是** | 0 ~ 720 | 观测时刻距灾害发生的小时数（最长 30 天）|
| 9 | `rescue_eta_hours` | float | **是** | 0 ~ 168 | 救援队预计还需多久抵达；已抵达填 0 |
| 10 | `road_accessibility` | float | **是** | 0.0 ~ 1.0 | 道路可通行性（0=完全阻断，1=完全畅通）|

## `disaster_type` 取值（必须严格匹配）

| 取值 | 含义 | 突发事件大类（参考） |
|---|---|---|
| `earthquake` | 地震 | 自然灾害 |
| `flood` | 洪水（含台风暴雨次生）| 自然灾害 |
| `landslide` | 滑坡 / 泥石流 | 自然灾害 |
| `forest_fire` | 森林/草原火灾 | 自然灾害 |
| `urban_fire` | 城市建筑火灾 / 工厂火灾 | 事故灾难 |

## `magnitude` 映射表（不同灾种统一到 3.0~8.5）

不同灾种的"强度"度量不同，统一映射到 3.0~8.5 区间，让 Student 跨灾种学习一致的强度语义。**取你能拿到的最贴近的那项**：

| 灾种 | 推荐填法 |
|---|---|
| `earthquake` | **直接填里氏震级**（如 8.0 = 汶川地震主震，6.5 = 四川长宁地震）|
| `flood` | 洪水等级 1→4.0、2→5.5、3→7.0、4(特大)→8.0；或用降雨量（mm）/100 截到 8.5 |
| `urban_fire` | 一般→3.5、较大→5.0、重大→6.5、特别重大→8.0 |
| `forest_fire` | 一般(<1km²)→3.5、较大(1~100km²)→5.0、重大(100~1000km²)→6.5、特别重大(>1000km²)→8.0 |
| `landslide` | 小型(<1万m³)→3.5、中型(1~10万)→5.0、大型(10~100万)→6.5、特大型(>100万)→8.0 |

如果实在没数据，宁可空着也不要拍脑袋——空着会进入 prompt v4（不确定性感知版）单独处理。

## `building_collapse_rate` 怎么估

- 优先：政府/学术报告里"完全倒塌建筑数 / 受影响建筑总数"
- 其次：新闻报道里的描述按经验粗估（"半数倒塌"→0.5、"几乎全毁"→0.9、"轻微受损"→0.05）
- 火灾场景：用"过火建筑数 / 区域建筑总数"代替
- 滑坡/洪水：用"被掩埋或冲毁建筑数 / 区域建筑总数"
- **不知道就留空**

## `estimated_trapped` 怎么估

- 优先：官方公布的"被困""失联""掩埋"人数
- 其次：报道时间点附近最可信的数字
- 不算已确认死亡的（已确认死亡不计入"被困"）
- 0 也是有效值（轻微事件、已疏散完成等）

## `temperature_c` 怎么取

- 灾害发生地点 + 观测时刻附近的实测气温
- 优先：当地气象站当日均温
- 次选：附近城市同日均温

## `hours_since_disaster` 怎么算

- 主震发生时刻 → 数据观测时刻的小时数
- 同一事件可以采多个时间点：例如汶川地震 → 1h（紧急响应初期）、24h（黄金窗口中段）、72h（窗口尾段）、168h（救援后期）
- **多时间点采样是这个 schema 最有价值的用法**——同一事件不同时点是天然的"被困者状态时间序列"

## `rescue_eta_hours` 怎么估

- 当时报道里"救援队需要 X 小时抵达"
- 已经抵达的填 `0`
- 永远不会到的（如完全孤立）填 `168`（一周）
- 救援多次到达不同区域：取主救援队抵达时间

## `road_accessibility` 怎么估

| 描述 | 数值参考 |
|---|---|
| 完全阻断（如汶川地震初期通往北川的所有路） | 0.0 ~ 0.1 |
| 严重受阻（仅徒步可入） | 0.1 ~ 0.3 |
| 部分通车（小型车辆） | 0.3 ~ 0.6 |
| 主干道通畅，次干道部分阻断 | 0.6 ~ 0.9 |
| 完全畅通 | 0.9 ~ 1.0 |

## 推荐数据源

| 灾种 | 来源 |
|---|---|
| 地震 | 中国地震台网 cenc.ac.cn、USGS、汶川/玉树/九寨沟等历史报告 |
| 洪水 | 应急管理部公报、中国水利公报、各省水文年鉴 |
| 滑坡 | 中国地质调查局、地质灾害月报 |
| 森林火灾 | 国家林业和草原局年报、应急管理部森林防火通报 |
| 城市火灾 | 应急管理部"国务院安委办通报"系列、2015 天津港爆炸、2019 响水化工厂爆炸 |
| 国际 | EM-DAT (emdat.be)、ReliefWeb、UNDRR |
| 学术 | CNKI 检索"灾后伤亡评估"、Disaster Reports of International Association for Earthquake Engineering |

## 现实期望

- 200 条全部真实非常困难。建议：**目标 50 条真实** + **150 条合成增强**
- 真实样本将作为评估集的标准答案；合成样本帮模型见过更广特征空间
- 如果暂时凑不齐 50 条，先从经典 5~10 起重大灾害挖（汶川、玉树、雅安、定结、彝良、芦山、九寨沟、漾濞、玛多 …）每个事件采 3~5 个时间点

## 字段缺失策略

- 转换脚本看到必填字段缺失会报错并指出哪一行
- 某行不愿丢弃但有 1~2 个字段缺失：用 `?` 占位，prompt 自动切到 v4（不确定性感知版）
- 缺失超过 3 个必填：转换脚本拒绝该行
